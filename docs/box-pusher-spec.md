# 推箱子小游戏需求与技术方案

## 1. 项目概述
- **项目定位**：轻量级推箱子小游戏，面向抖音小游戏渠道，强调“闯关耗时竞争 + 排行榜”。
- **核心目标**：提供低门槛玩法体验，记录玩家通关耗时并在排行榜中对比，以激发重复挑战。
- **发行平台**：抖音小游戏（无需账号登录，使用平台游客标识）。

## 2. 功能需求

### 2.1 核心游戏循环
1. 玩家选择或系统推荐关卡。
2. 进入关卡，控制角色移动与推箱，支持撤销一步与重新开始。
3. 所有箱子推入目标点即通关，记录耗时与步数。
4. 成绩上传抖音排行榜；展示个人最佳与全服排名。

### 2.2 关卡与数据
- 关卡以 JSON 配置（地图矩阵、起点、箱子、目标、障碍）。
- 默认包含 30 个基础关卡，可扩展章节。
- 关卡难度：通过箱子数量、机关类型（冰面、单向门、传送点）配置。
- 内置本地关卡编辑能力（调试阶段使用），正式版只读。

### 2.3 计时与排行榜
- 计时器：进入关卡开始计算，暂停时（广告/切后台）冻结。
- 支持记录以下字段：关卡 ID、耗时、步数、撤销次数、时间戳。
- 排行榜类型：
  - 全服最快（抖音平台推荐榜）。
  - 好友榜（利用抖音社交关系）。
  - 本地历史最佳（离线可查）。

### 2.4 广告植入
- 激励广告：通关后可观看获得“提示”或“下一关预览”；每关最多 1 次。
- 插屏广告：连续失败 3 次或连续通关 3 局后触发，首局免广告。
- 广告播放中暂停计时，失败/跳过需回退状态并提示。

### 2.5 抖音平台适配
- 竖屏 9:16，主 UI 采用 Safe Area。
- 接入抖音小游戏 SDK：游客 ID、排行榜、激励/插屏广告、分享。
- 无需自建登录/支付；如需素材分享使用平台接口。

## 3. 技术方案

### 3.1 技术栈
- **引擎**：Cocos Creator 3.x（TypeScript）。
- **渲染**：2D Tilemap + 精灵动画。
- **数据**：JSON/CSV 转换脚本 + TypeScript 类型生成。
- **构建**：Cocos Creator 抖音小游戏导出 + 抖音 DevTools 调试。

### 3.2 模块划分
- `GameScene`：地图渲染、角色控制、推箱逻辑、撤销栈。
- `TimerService`：统一计时、暂停、格式化显示。
- `RankingService`：封装抖音排行榜 API（提交、拉取、错误回退）。
- `AdService`：加载/展示激励与插屏，提供成功/失败回调。
- `StorageService`：本地最佳成绩、设置项（音量、控制方式）。
- `LevelLoader`：读取关卡 JSON，校验数据完整性。
- `UI`：Lobby（关卡列表 + 排行榜入口）、HUD（计时、步数、撤销、提示）、ResultOverlay（成绩与分享）。

### 3.3 数据结构示例
```json
{
  "id": "level_010",
  "size": [10, 10],
  "player": [1, 1],
  "boxes": [[2, 4], [4, 5]],
  "targets": [[7, 6], [6, 2]],
  "tiles": [
    "##########",
    "#@......T#",
    "#.##B##..#"
  ],
  "mechanics": {
    "ice": [[3, 4]],
    "oneWay": [[[5, 5], "up"]]
  }
}
```

### 3.4 关键算法/逻辑
- **推箱判定**：基于网格数组，检测下一格是否可推（空或目标）；若是箱子，继续检查前一格。
- **撤销**：栈记录（玩家坐标、箱子矩阵、计时点）；限制最大步数避免内存暴涨。
- **提示系统**：使用 IDA* 或 BFS 搜索最短步数路径，限定节点数以控制性能。
- **广告 & 计时联动**：展示广告前暂停定时器，回调成功/失败后恢复，确保上传的数据准确。

## 4. 开发计划（4 周）
| 周次 | 核心目标 | 里程碑 |
| --- | --- | --- |
| Week1 | 推箱核心、关卡加载、HUD | 通关流程跑通 |
| Week2 | 排行榜、成绩上报、本地存档 | 抖音排行榜调通 |
| Week3 | 广告 SDK、界面美化、音效 | 激励/插屏可控触发 |
| Week4 | 打包适配、性能/兼容测试、审核 | 抖音提审版本 |

## 5. 测试要点
- 计时准确性（切后台、广告播放、暂停后恢复）。
- 排行榜上传频次与异常处理（网络失败、重复提交）。
- 广告加载失败兜底流程（重试、降级提示）。
- 关卡数据完整性（箱子与目标数量相等、无死图）。
- 性能：低端机 30fps 以上，内存峰值 < 200MB。

## 6. 风险与对策
- **广告体验影响**：通过冷却与首局豁免控制频率；数据埋点观察留存。
- **抖音审核**：严格遵循素材、文案、适龄提示要求，预留 1 周审核缓冲。
- **关卡重复率**：定期更新关卡包，结合数据分析投放高参与度地图。
- **排行榜外挂**：客户端仅上传成绩，服务端（抖音）做阈值校验，超出合理范围的成绩标记异常。

## 7. 界面布局描述（供效果图参考）

### 7.1 大厅（Lobby）
- **背景**：淡色渐变（#F6F8FB → #D8E8FF），中央模糊棋盘纹理，凸显休闲风。
- **顶部区域**：左侧显示游戏 Logo（卡通箱子 + 箭头），右侧为设置按钮与音效开关图标。
- **中部主卡片**：
  - 900×600 px（9:16 竖屏内居中），圆角 24 px，浅色面板。
  - 上方显示当前推荐关卡插画（简化等距地图）。
  - 下方双列按钮：`开始`（主色 #FF7B3F）与 `排行榜`（次色白底描边）。
- **底部导航**：三按钮（`关卡`、`自我挑战`、`广告奖励`），图标 + 12pt 文字，常驻浮层。

### 7.2 游戏内 HUD
- **背景**：灰蓝棋盘（64 px 格），箱子/角色采用高饱和度色块。
- **顶部信息条**：
  - 左侧：计时器（数字字体，主色 #FF7B3F）。
  - 中间：步数与撤销次数。
  - 右侧：暂停按钮 + 重开按钮。
- **底部操作区**：
  - 左侧：虚拟摇杆（默认隐藏，玩家可在设置中启用）。
  - 右侧：两个圆形按钮（撤销、提示/激励广告入口），附带冷却或次数提示。
- **提示弹框**：半透明黑背景 + 白字说明，出现于顶部中央，展示操作提示或广告奖励提醒。

### 7.3 结算覆盖层（Result Overlay）
- **背景**：半透明黑，中央白色卡片。
- **卡片内容**：
  - 胜利动画（小箱子跳跃）。
  - 数据：耗时、步数、最佳成绩比较（绿色上/下降箭头）。
  - 按钮：`重试`、`下一关`、`观看激励广告获取提示`。
- **排行榜入口**：卡片下方横向滑入，展示前三名头像/昵称/耗时，点击进入完整榜单。

### 7.4 排行榜页
- **顶部切换**：`全服` / `好友` / `历史最佳`，使用 Pill Style 标签。
- **排行榜列表**：卡片式条目，左侧排名数字（前 3 使用金银铜徽章），中间玩家昵称（抖音游客 ID 映射）与耗时，右侧时间戳。
- **滤镜背景**：轻微模糊的游戏场景截图，保持层级感。
