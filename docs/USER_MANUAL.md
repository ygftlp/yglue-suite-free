# Ygflow Suite 使用手册（内部版）

## 1. 使用前提
- 拥有统一认证系统账号，并被授予对应项目的访问权限。
- 浏览器建议使用 Chrome 110+ 或同等内核版本，IDE 环境需安装 IntelliJ IDEA 2023.3 及以上，JDK 17。
- 网络需可访问公司内部 API 网关、配置中心以及镜像仓库；若在分支机构，需提前配置代理或 VPN。

## 2. 环境准备
### 2.1 Web 工作台
- 通过统一入口访问 Orchestrator UI，首次登录需选择或创建项目。
- 建议与 Git 平台的项目结构保持一致，便于团队协作。

### 2.2 IntelliJ IDEA 插件
- 在 `yglue-idea-plugin` 目录执行 `.\gradlew.bat build`，首次运行若下载缓慢，可修改 `gradle-wrapper.properties` 使用内网镜像并提高 `networkTimeout`。
- 在 IDEA 中通过 `File → Settings → Plugins → Install Plugin from Disk...` 安装生成的插件包，或从内部插件仓库安装。
- 插件要求 JDK 17 环境，确保 `JAVA_HOME` 正确配置并能在终端执行 `java -version`。

## 3. 快速开始
1. **创建流程**：在 Web 画布中新建流程或复制模板，拖拽入口节点、任务节点、转换器等。
2. **配置节点**：选中节点后在右侧 Inspector 面板填写接口信息、超时、回调等业务参数。
3. **数据转换**：通过 Transformer Editor 完成字段映射、集合处理、条件逻辑，并可追加 Groovy 脚本。
4. **参数解析**：在 Param Resolver 中维护流程所需的上下文参数，必要时使用表达式或脚本转换。
5. **调试验证**：使用调试面板输入参数运行流程，检查返回数据与日志。
6. **提交发布**：流程验证通过后，提交审核并按项目的发布流程上线。

## 4. 日常操作
### 4.1 画布操作
- 支持节点多选、快捷复制、对齐与网格吸附，可通过快捷键加快建模速度。
- 节点之间支持连线校验，仅允许符合类型约束的连接。

### 4.2 版本管理
- 每次保存或发布都会生成流程版本，可在版本列表中进行差异比对与回滚。
- 建议按照环境（开发/测试/生产）分别维护流程，避免直接覆盖线上版本。

### 4.3 IDE 协同
- 插件支持从平台拉取流程元数据到本地进行离线编辑，保存后可一键上传。
- 变更提醒与心跳任务会定期检查本地配置是否与平台一致，发现冲突时会提示人工处理。

### 4.4 权限与审计
- 项目负责人可在平台内设置成员角色、审批流程与操作日志查看范围。
- 所有发布行为都会记录执行人、时间、版本号和变更摘要，满足内部审计要求。

## 5. 环境与发布
- 建议配合公司的 CI/CD 流程：开发环境完成自测后，将流程导出或提交到 Git，触发自动化校验，再由发布平台部署到测试/生产。
- 如需为不同环境设置变量，可在流程配置中启用环境参数功能，统一管理网关地址、鉴权信息等。

## 6. 故障排查
- **Gradle 下载超时**：在 `gradle-wrapper.properties` 中使用内网镜像（如阿里云、腾讯云）并提高 `networkTimeout`，或手动下载包后配置本地路径。
- **依赖无法解析**：确保执行过 `gradlew build` 并刷新 IDEA Gradle 项目；若使用代理，在 `%USERPROFILE%\.gradle\gradle.properties` 中配置代理信息。
- **流程运行异常**：使用调试面板查看日志与输出，确认必填字段、参数解析和脚本是否完整；必要时启用运行时 trace。
- **插件同步失败**：检查网络与认证状态，查看 IDEA Event Log 中的错误详情；如为版本兼容问题，可从内部仓库获取最新插件。

## 7. 注意事项
- 所有流程、脚本、配置均属公司内部资产，不得对外传播或用于商业化场景。
- 处理敏感数据时应遵守信息安全与数据分级要求，必要时脱敏或申请审批。
- 建议对关键流程建立双人审核机制，并配合单元/集成测试保障质量。
