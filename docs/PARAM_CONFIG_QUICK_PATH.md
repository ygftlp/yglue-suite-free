# 入参配置最短路径（V2）

## 1. 目标
为普通用户提供最短操作路径：
- 单值入参：1 分钟内完成。
- 对象入参：通过字段映射一次性完成。
- List 入参：先拿列表，再做字段组装，最后按需后处理。

## 2. 前置条件（必须）
平台可用性高度依赖“本地项目元数据上报”，建议由 IDEA 插件自动同步以下信息：
1. 服务目录：`serviceBean`、`method`、`methodSignature`、返回类型。
2. 方法入参：参数名、Java 类型、是否必填、参数说明。
3. 入参 Schema：对象字段结构（含嵌套）、List 元素类型。
4. 字段约束（只读提示）：`min/max/pattern/enum/required`。
5. 分支可用变量：请求上下文、临时变量（节点作用域/流程作用域）。

没有这些元数据时，用户仍可手工配置，但效率与正确率会明显下降。

## 3. 单值入参（最短 3 步）
1. 在“服务调用”中选择方法。
2. 在参数行点击“配置”，来源选 `ctx/request`、`常量` 或 `临时变量`。
3. 保存并返回。

校验建议：
- 单值参数只允许一个计划。
- 常量值需与目标类型兼容（例如 String/Number/Boolean）。

## 4. 对象入参（推荐路径）
1. 选择方法后，进入对象参数配置弹框。
2. 切换到“对象构造器”。
3. 点击“按类型生成字段”，系统自动生成字段映射。
4. 逐字段选择来源（ctx/常量/临时变量），必要时调整路径。

校验建议：
- 字段路径不能重复。
- 必填字段必须有来源。
- 类型不匹配给告警，不直接阻断编辑。

## 5. List 入参（分散来源组装）
1. 在“参数构造管线（V2）”选择 `List 管线`。
2. 配置 List 输入源（ctx、服务返回 List、常量 List）。
3. 在“目标元素字段映射”中逐字段配置来源。
4. 仅在必要时添加后处理步骤（filter/map/enrich/groupBy/reduce）。

性能建议：
- 默认禁止在 List 后处理里做循环服务调用。
- 需要补数时，先在临时变量阶段聚合取数，再映射引用。

## 6. 分支配置（给普通用户）
推荐“边上配置”而非节点内配置：
1. 分支条件写在线条上。
2. 每条线有优先级。
3. 分支节点只做临时变量预计算，供线条件引用。

这样能减少“条件写在节点里但作用在线上”的认知错位。

## 7. 当前方案可覆盖的场景
1. 单值参数直取/常量赋值。
2. 对象参数按字段组装（含嵌套）。
3. List 参数从分散来源组装目标元素。
4. 服务返回对象后按路径提取子属性。
5. 参数依赖前置计算（临时变量）。

## 8. 仍不建议直接覆盖的场景
1. 超复杂循环内服务调用（性能不可控）。
2. 强业务语义的复杂表达式拼装。

建议方式：
- 将复杂逻辑前置到“临时变量计划”或项目内稳定服务，再在 V2 中做组合与映射。
