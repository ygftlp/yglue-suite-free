# LiteFlow 流程设计器优化建议

## 当前状态分析

### ✅ 已实现的功能
1. **基础流程编排**：支持节点拖拽、连线、删除等基本操作
2. **节点类型支持**：
   - `task` - 任务节点（业务组件）
   - `branch` - 分支节点（条件判断）
   - `transaction` - 事务节点（开始/结束）
   - `transformer` - 脚本节点（数据转换和响应构造）
3. **节点配置**：支持输入参数、输出结果、执行参数等配置
4. **流程保存/发布**：支持草稿保存和流程发布

### ⚠️ 需要优化的地方

#### 1. LiteFlow EL 表达式生成
**问题**：当前的 `generateLiteFlowRule` 函数只生成预览文本，不是真正的 LiteFlow EL 表达式格式。

**LiteFlow 规则格式示例**：
```el
chain("chain1") = THEN(a, b, c)
chain("chain2") = IF(x, THEN(a, b), ELSE(c, d))
chain("chain3") = SWITCH(s).TO(a, b, c)
```

**优化方案**：
- 实现真正的 LiteFlow EL 表达式生成器
- 将节点 ID 映射到组件名称（如 `bean.method`）
- 支持 THEN、IF、ELSE、SWITCH 等 LiteFlow 语法
- 处理分支条件表达式

#### 2. 节点 ID 到组件名称的映射
**问题**：当前使用节点 ID（如 `1234567890`），但 LiteFlow 需要组件名称。

**优化方案**：
- 对于 `task` 节点：使用 `bean.method` 格式（如 `userService.createUser`）
- 对于 `transformer` 节点：使用脚本组件名称
- 对于 `branch` 节点：需要特殊处理，映射到 IF 条件组件

#### 3. 分支条件表达式处理
**问题**：分支节点的条件表达式需要正确映射到 LiteFlow 的 IF/ELSE 结构。

**优化方案**：
- 支持在连线上配置条件表达式
- 将分支节点转换为 LiteFlow 的 IF 条件组件
- 处理多个分支的情况（SWITCH）

#### 4. 事务节点支持
**问题**：需要确保事务节点正确映射到 LiteFlow 的事务特性。

**优化方案**：
- 事务开始节点：标记后续节点在同一事务中
- 事务结束节点：标记事务边界
- 在 EL 表达式中正确表达事务范围

#### 5. 规则验证
**问题**：缺少对生成的 LiteFlow 规则的验证。

**优化方案**：
- 验证节点 ID 是否都有对应的组件
- 验证分支条件表达式是否有效
- 验证流程是否有循环依赖
- 验证事务节点是否成对存在

## 技术实现细节

### 节点类型映射
- `task` → LiteFlow 普通组件（`bean.method`）
- `branch` → LiteFlow IF 条件组件
- `transformer` → LiteFlow 脚本组件
- `transaction` → LiteFlow 事务标记

### EL 表达式生成规则
1. **顺序执行**：`THEN(a, b, c)`
2. **条件分支**：`IF(condition, THEN(a, b), ELSE(c, d))`
3. **并行执行**：`WHEN(a, b, c)`
4. **循环执行**：`FOR(condition).DO(a, b)`

### 组件名称生成规则
- 优先使用 `comp.bean` 和 `comp.method`
- 如果没有，使用节点 ID 作为占位符
- 脚本节点使用特殊前缀（如 `script_xxx`）
