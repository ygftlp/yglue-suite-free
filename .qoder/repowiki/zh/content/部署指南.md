## 简介
YGFlow Suite 是一个企业级业务流程低代码编排平台，包含编排器服务、前端应用、运行时引擎和IDE插件等多个组件。本部署指南旨在为运维人员和高级开发者提供在生产环境中部署YGFlow Suite的完整指导，涵盖从环境准备到高可用性配置的全过程。

## 环境要求
### 操作系统
YGFlow Suite 可在以下操作系统上运行：
- Linux (推荐 CentOS 7+/Ubuntu 18.04+)
- Windows Server 2016+
- macOS (仅用于开发测试)

### Java环境
- **JDK版本**: 17或更高版本
- **推荐发行版**: OpenJDK 17 LTS 或 Oracle JDK 17
- **环境变量**: 需正确配置 `JAVA_HOME` 环境变量

### 构建工具
- **Maven**: 3.8或更高版本
- **Gradle**: 8.x (仅用于IDE插件构建)

### 前端环境
- **Node.js**: 18或更高版本
- **npm**: 9.x或更高版本

### 数据库
- **MySQL**: 8.0或更高版本
- **数据库配置**: 
  - 字符集: utf8mb4
  - 排序规则: utf8mb4_unicode_ci
  - 最大连接数: 建议设置为 500 或更高
  - 连接超时: 建议设置为 300 秒

### 硬件建议
- **CPU**: 4核或更高
- **内存**: 8GB RAM 或更高 (建议16GB用于生产环境)
- **存储**: 50GB 或更高 (根据数据量调整)
- **网络**: 1Gbps 网络连接

## 构建步骤
### 编排器服务构建
编排器服务是YGFlow Suite的核心后端服务，使用Maven进行构建。

```bash
# 进入项目根目录
cd 

# 清理并安装所有模块
mvn clean install

# 或者单独构建编排器服务
cd yglue-orchestrator
mvn clean package
```

构建完成后，可在 `yglue-orchestrator/target/` 目录下找到生成的JAR文件，文件名通常为 `yglue-orchestrator-*.jar`。

### 前端应用构建
前端应用使用Vite和npm进行构建。

```bash
# 进入前端应用目录
cd apps/ygflow-orchestrator-ui

# 安装依赖
npm install

# 构建生产版本
npm run build
```

构建完成后，静态文件将生成在 `dist/` 目录下，可部署到Web服务器。

### 样例服务构建
样例服务展示了如何在现有Spring Boot应用中集成YGFlow运行时。

```bash
# 进入样例服务目录
cd samples/yglue-sample-service

# 构建样例服务
mvn clean package
```

## 配置文件说明
### 编排器服务配置 (application.yml)
编排器服务的主要配置文件位于 `yglue-orchestrator/src/main/resources/application.yml`。

```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/yglue?useSSL=false&useUnicode=true&characterEncoding=utf8&serverTimezone=UTC
    username: root
    password: root

mybatis:
  mapper-locations: classpath*:mapper/**/*.xml
  type-aliases-package: org.yglue.flow.orch.domain

server:
  port: 8091

logging:
  level:
    root: INFO
    org.yglue.flow.orch: DEBUG
  file:
    name: logs/ygflow-orchestrator.log
  pattern:
    console: "%d{HH:mm:ss.SSS} %-5level [%thread] %logger{36} - %msg%n"
```

#### 关键参数说明
- **spring.datasource.url**: 数据库连接URL，生产环境中应修改为实际的数据库地址
- **spring.datasource.username/password**: 数据库认证凭据，生产环境中应使用安全的凭据管理
- **server.port**: 服务监听端口，默认为8091
- **logging.file.name**: 日志文件路径，建议配置到独立的存储位置
- **mybatis.mapper-locations**: MyBatis映射文件位置

#### 调优建议

## 服务启动与停止
### 编排器服务
#### 启动脚本
创建启动脚本 `start-orchestrator.sh`:

```bash
#!/bin/bash

# 服务名称
SERVICE_NAME="ygflow-orchestrator"
# JAR文件路径
JAR_PATH="/opt/ygflow/yglue-orchestrator-0.1.0-SNAPSHOT.jar"
# 日志目录
LOG_DIR="/var/log/ygflow"
# PID文件
PID_FILE="/var/run/$SERVICE_NAME.pid"

# 创建日志目录
mkdir -p $LOG_DIR

# JVM参数
JVM_OPTS="-Xms4g -Xmx4g -XX:MetaspaceSize=256m -XX:MaxMetaspaceSize=512m"
JVM_OPTS="$JVM_OPTS -XX:+UseG1GC -XX:MaxGCPauseMillis=200"
JVM_OPTS="$JVM_OPTS -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=$LOG_DIR"

# 应用参数
APP_OPTS="--spring.profiles.active=prod"
APP_OPTS="$APP_OPTS --logging.file.name=$LOG_DIR/orchestrator.log"

# 启动服务
nohup java $JVM_OPTS -jar $JAR_PATH $APP_OPTS > $LOG_DIR/startup.log 2>&1 &

# 保存PID
echo $! > $PID_FILE

echo "YGFlow Orchestrator started with PID $!"
```

#### 停止脚本
创建停止脚本 `stop-orchestrator.sh`:

```bash
#!/bin/bash

# PID文件
PID_FILE="/var/run/ygflow-orchestrator.pid"

if [ -f $PID_FILE ]; then
    PID=$(cat $PID_FILE)
    if ps -p $PID > /dev/null; then
        echo "Stopping YGFlow Orchestrator (PID: $PID)..."
        kill -15 $PID
        
        # 等待服务优雅关闭
        sleep 10
        
        # 强制终止仍在运行的进程
        if ps -p $PID > /dev/null; then
            echo "Force stopping..."
            kill -9 $PID
        fi
        
        # 删除PID文件
        rm -f $PID_FILE
        echo "YGFlow Orchestrator stopped."
    else
        echo "Process not running."
        rm -f $PID_FILE
    fi
else
    echo "PID file not found. Service may not be running."
fi
```

#### 重启脚本
创建重启脚本 `restart-orchestrator.sh`:

```bash
#!/bin/bash

echo "Restarting YGFlow Orchestrator..."
./stop-orchestrator.sh
sleep 5
./start-orchestrator.sh
```

## 日志管理
### 日志级别配置
YGFlow Suite使用Spring Boot的Logging框架，支持多种日志级别：

- **TRACE**: 最详细的日志信息，包括HTTP请求的完整细节
- **DEBUG**: 调试信息，用于开发和问题排查
- **INFO**: 一般信息，记录主要操作和状态变化
- **WARN**: 警告信息，表示潜在问题
- **ERROR**: 错误信息，表示发生错误但服务仍可运行
- **FATAL**: 严重错误，可能导致服务终止

推荐的生产环境日志级别配置：
```yaml
logging:
  level:
    root: INFO
    org.yglue.flow.orch: WARN
    org.springframework: WARN
    org.mybatis: WARN
```

### 日志文件管理
#### 文件轮转配置
```yaml
logging:
  file:
    name: logs/ygflow-orchestrator.log
  logback:
    rollingpolicy:
      max-file-size: 100MB
      max-history: 30
      total-size-cap: 10GB
```

#### 集中式日志收集
建议使用ELK（Elasticsearch, Logstash, Kibana）或EFK（Elasticsearch, Fluentd, Kibana）堆栈进行集中式日志管理。

**Fluentd配置示例**:
```xml
<source>
  @type tail
  path /var/log/ygflow/*.log
  pos_file /var/log/td-agent/ygflow.pos
  tag ygflow.*
  format json
  read_from_head true
</source>

<match ygflow.**>
  @type elasticsearch
  host elasticsearch.example.com
  port 9200
  logstash_format true
  logstash_prefix ygflow
  flush_interval 10s
</match>
```

### 日志安全
1. **敏感信息过滤**: 确保日志中不包含密码、密钥等敏感信息
2. **访问控制**: 限制对日志文件的访问权限
3. **加密存储**: 对包含敏感信息的日志进行加密存储
4. **定期清理**: 设置日志保留策略，定期清理旧日志

### 告警配置
#### Grafana告警规则
```yaml
groups:
  - name: ygflow-alerts
    rules:
      - alert: ServiceDown
        expr: up{job="ygflow-orchestrator"} == 0
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "YGFlow Orchestrator is down"
          description: "YGFlow Orchestrator has been down for more than 5 minutes."

      - alert: HighErrorRate
        expr: rate(http_server_requests_seconds_count{status="5xx"}[5m]) / rate(http_server_requests_seconds_count[5m]) > 0.05
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: "High error rate in YGFlow Orchestrator"
          description: "Error rate is above 5% for the last 10 minutes."

      - alert: HighLatency
        expr: histogram_quantile(0.95, sum(rate(http_server_requests_seconds_bucket[5m])) by (le)) > 1
        for: 10m
        labels:
          severity: warning
        annotations:
          summary: "High latency in YGFlow Orchestrator"
          description: "95th percentile latency is above 1 second for the last 10 minutes."
```

## 高可用性部署建议
### 负载均衡配置
#### Nginx负载均衡

```nginx
upstream ygflow_orchestrator {

server {
    listen 80;
    server_name orchestrator.example.com;

        proxy_pass http://ygflow_orchestrator;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # 超时设置

        proxy_send_timeout 60s;
        proxy_read_timeout 60s;

}
```

### 数据库高可用
#### MySQL主从复制
1. **主库配置** (`my.cnf`):
```ini
[mysqld]
server-id=1
log-bin=mysql-bin
binlog-format=row
binlog-do-db=yglue
```

2. **从库配置** (`my.cnf`):
```ini
[mysqld]
server-id=2
relay-log=mysqld-relay-bin
read-only=1
```

3. **主库创建复制用户**:
```sql
CREATE USER 'repl'@'%' IDENTIFIED BY 'password';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'%';
FLUSH PRIVILEGES;
```

4. **从库配置复制**:
```sql
CHANGE MASTER TO
  MASTER_HOST='master-host',
  MASTER_USER='repl',
  MASTER_PASSWORD='password',
  MASTER_LOG_FILE='mysql-bin.000001',
  MASTER_LOG_POS=107;
  
START SLAVE;
```

### 容灾与备份
#### 数据库备份策略
1. **全量备份**:
```bash
# 每天凌晨2点执行全量备份
0 2 * * * mysqldump -u root -p yglue | gzip > /backup/yglue-$(date +\%Y\%m\%d).sql.gz
```

2. **增量备份**:
```bash
# 启用二进制日志
log-bin=mysql-bin
# 定期备份二进制日志
0 3 * * * mysqlbinlog mysql-bin.* > /backup/binlog-$(date +\%Y\%m\%d).sql
```

#### 灾难恢复计划
1. **RTO (恢复时间目标)**: 30分钟
2. **RPO (恢复点目标)**: 5分钟
3. **恢复步骤**:
