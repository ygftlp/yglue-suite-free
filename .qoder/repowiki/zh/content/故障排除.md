## 简介

YGFlow Suite 是一个面向企业级业务流程的低代码编排平台，覆盖"开发者 IDE → 可视化设计台 → 运行时引擎"的全链路。本故障排除指南旨在帮助用户诊断和解决在使用 YGFlow Suite 过程中遇到的常见问题，包括编排器服务启动失败、前端无法访问、IDEA 插件同步失败、流程执行异常、参数解析错误、数据转换失败等场景。同时提供日志分析技巧和性能问题的初步排查方法。

## 编排器服务启动失败

### 症状描述
编排器服务（yglue-orchestrator）启动时失败，无法正常运行。

### 可能的根本原因
1. **数据库连接错误**：编排器服务依赖 MySQL 数据库，如果数据库未启动或连接配置错误，服务将无法启动。
2. **端口冲突**：编排器服务默认使用 8091 端口，如果该端口已被其他进程占用，服务将无法启动。
3. **Java 版本不兼容**：编排器服务需要 Java 17+ 版本，如果环境中的 Java 版本过低，可能导致启动失败。

### 解决步骤
1. **检查数据库连接**：
   - 确认 MySQL 服务已启动。
   - 检查 `yglue-orchestrator/src/main/resources/application.yml` 文件中的数据库连接配置是否正确。
   - 确保数据库用户名和密码正确，并且有相应的访问权限。

2. **检查端口占用**：
   - 使用 `netstat -an | grep 8091` 命令检查 8091 端口是否已被占用。
   - 如果端口被占用，可以修改 `application.yml` 文件中的 `server.port` 配置，更换为其他可用端口。

3. **检查 Java 版本**：
   - 运行 `java -version` 命令检查 Java 版本。
   - 确保 Java 版本为 17 或更高版本。

4. **查看日志信息**：
   - 检查 `logs/ygflow-orchestrator.log` 日志文件，查找具体的错误信息。
   - 根据日志中的错误提示进行相应的修复。

## 前端无法访问

### 症状描述
前端应用（ygflow-orchestrator-ui）无法正常访问，页面加载失败或显示空白。

### 可能的根本原因
1. **代理配置错误**：前端应用通过代理请求后端 API，如果代理配置错误，将无法访问后端服务。
2. **编排器服务未启动**：前端依赖编排器服务提供数据，如果编排器服务未启动，前端将无法获取数据。
3. **网络问题**：前端与后端之间的网络连接存在问题，导致请求失败。

### 解决步骤
1. **检查代理配置**：
   - 检查 `apps/ygflow-orchestrator-ui/vite.config.ts` 文件中的代理配置是否正确。
   - 确认 `apiTarget` 配置的地址与编排器服务的实际地址一致。

2. **确认编排器服务状态**：
   - 确保编排器服务已成功启动。
   - 访问 `http://localhost:8091/api/health` 检查编排器服务的健康状态。

3. **检查网络连接**：
   - 确认前端和后端服务在同一网络环境中。
   - 使用 `ping` 命令测试前端与后端之间的网络连通性。

4. **查看浏览器控制台**：
   - 打开浏览器开发者工具，查看控制台是否有错误信息。
   - 检查网络请求是否成功，失败的请求会显示具体的错误原因。

## IDEA插件同步失败

### 症状描述
IntelliJ IDEA 插件无法与编排器服务同步流程规则，导致元数据和规则文件无法更新。

### 可能的根本原因
1. **服务器端点配置错误**：插件配置的服务器端点地址不正确，导致无法连接到编排器服务。
2. **项目标识错误**：插件配置的项目标识（projectKey）与编排器服务中的项目不匹配。
3. **网络防火墙限制**：网络防火墙阻止了插件与编排器服务之间的通信。

### 解决步骤
1. **检查服务器端点配置**：
   - 在 IDEA 插件设置中，确认服务器端点地址是否正确。
   - 默认地址为 `http://localhost:8091`，如果编排器服务运行在其他地址，需要相应修改。

2. **验证项目标识**：
   - 确认插件配置的项目标识与编排器服务中的项目标识一致。
   - 可以在编排器服务的项目管理界面查看正确的项目标识。

3. **测试连接**：
   - 在插件设置界面点击"测试连接"按钮，检查是否能成功连接到编排器服务。
   - 如果连接失败，查看具体的错误信息进行修复。

4. **检查防火墙设置**：
   - 确认网络防火墙没有阻止插件与编排器服务之间的通信。
   - 如果在公司网络环境下，可能需要联系网络管理员开放相应端口。

## 流程执行异常

### 症状描述
流程在执行过程中出现异常，无法正常完成。

### 可能的根本原因
1. **节点配置错误**：流程中的某个节点配置不正确，导致执行失败。
2. **服务调用失败**：服务节点调用的外部服务不可用或返回错误。
3. **表达式计算错误**：流程中使用的 SpEL 表达式存在语法错误或计算失败。

### 解决步骤
1. **查看执行日志**：
   - 检查运行时引擎的日志，查找具体的错误信息。
   - 日志中通常会记录失败的节点和错误原因。

2. **检查节点配置**：
   - 在可视化设计台中检查流程中各节点的配置是否正确。
   - 特别关注服务节点的接口地址、参数映射等配置。

3. **验证服务可用性**：
   - 手动测试服务节点调用的外部服务是否可用。
   - 使用 Postman 等工具直接调用服务接口，确认返回结果是否符合预期。

4. **调试表达式**：
   - 如果使用了 SpEL 表达式，可以在设计台的表达式调试器中测试表达式的计算结果。
   - 确保表达式语法正确，并且引用的变量存在。

## 参数解析错误

### 症状描述
流程执行时参数解析失败，导致后续节点无法获取正确的输入参数。

### 可能的根本原因
1. **参数来源配置错误**：参数解析器配置的来源字段不存在或拼写错误。
2. **必填参数缺失**：配置为必填的参数在请求中缺失。
3. **参数类型不匹配**：传入的参数类型与期望的类型不一致。

### 解决步骤
1. **检查参数解析器配置**：
   - 在可视化设计台中检查各节点的参数解析器配置。
   - 确认来源字段名称与请求中的字段名称完全匹配。

2. **验证请求参数**：
   - 检查发起请求时是否包含了所有必需的参数。
   - 使用浏览器开发者工具或抓包工具查看实际的请求参数。

3. **查看验证错误**：
   - 如果参数验证失败，运行时引擎会抛出 `ValidationException`。
   - 检查日志中的错误信息，了解具体的验证失败原因。

4. **调整参数类型**：
   - 如果存在类型不匹配问题，可以在参数解析器中添加类型转换配置。
   - 或者修改请求，确保传入正确的参数类型。

## 数据转换失败

### 症状描述
数据转换节点执行失败，无法正确转换数据格式。

### 可能的根本原因
1. **转换规则配置错误**：Transformer 的转换规则配置不正确，如字段映射错误。
2. **脚本执行失败**：Groovy 脚本存在语法错误或运行时异常。
3. **必填字段缺失**：配置为必填的输出字段在转换过程中缺失。

### 解决步骤
1. **检查转换规则**：
   - 在可视化设计台中检查 Transformer 的转换规则。
   - 确认输入源和输出目标的配置是否正确。

2. **调试 Groovy 脚本**：
   - 如果使用了 Groovy 脚本，可以在设计台的脚本编辑器中进行调试。
   - 添加日志输出，查看脚本执行过程中的变量值。

3. **验证输入数据**：
   - 检查输入数据是否符合转换规则的预期。
   - 确保输入数据中包含转换规则所需的所有字段。

4. **查看转换错误**：
   - 检查运行时引擎的日志，查找数据转换失败的具体错误信息。
   - 根据错误提示调整转换规则。

## 性能问题排查

### 症状描述
系统出现高延迟或高 CPU 使用率，影响正常运行。

### 可能的根本原因
1. **流程复杂度过高**：流程包含过多节点或复杂的条件分支，导致执行时间过长。
2. **数据库查询性能问题**：频繁的数据库查询或慢查询导致性能下降。
3. **资源不足**：服务器的 CPU、内存等资源不足，无法满足系统需求。

### 解决步骤
1. **分析流程性能**：
   - 使用系统提供的性能监控工具，分析各流程的执行时间。
   - 识别执行时间过长的流程，进行优化。

2. **优化数据库查询**：
   - 检查数据库慢查询日志，找出执行时间过长的 SQL 语句。
   - 为常用查询字段添加索引，优化查询性能。

3. **监控系统资源**：
   - 使用系统监控工具查看 CPU、内存、磁盘 I/O 等资源使用情况。
   - 如果资源使用率持续过高，考虑升级服务器配置。

4. **调整线程池配置**：
   - 检查运行时引擎的线程池配置，确保线程数适合当前负载。
   - 根据实际需求调整线程池大小，避免线程过多导致上下文切换开销过大。
