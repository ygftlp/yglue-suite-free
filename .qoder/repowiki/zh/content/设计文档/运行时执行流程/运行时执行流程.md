## 引言

本文档旨在深入解析运行时引擎的执行流程，从接收到一个REST请求开始，到流程执行完成并返回响应的完整生命周期。文档将详细阐述`FlowDispatchInterceptor`如何拦截请求，`FlowExecutor`如何加载并执行流程定义，`NodeExecutorRegistry`如何根据节点类型调度具体的执行器（如`ServiceNodeExecutor`、`RestNodeExecutor`），以及`ExecutionInterceptor`如何处理执行过程中的事件。同时，结合代码实例，说明上下文（`FlowContext`）的传递和节点间的数据流转机制。

**本文档不分析具体源文件，因此不提供章节来源。**

## 执行流程总览

一个完整的流程执行生命周期可以分为以下几个阶段：
1.  **请求拦截**：`FlowDispatchInterceptor`拦截所有进入的HTTP请求。
2.  **请求匹配**：根据请求的路径和方法，在`RestEntryPointRegistry`中查找匹配的流程入口点。
3.  **参数提取与校验**：使用`FlowRequestPayloadExtractor`提取请求体、路径参数、查询参数等，并通过`RequestSchemaValidator`进行参数校验。
4.  **流程执行**：调用`RuleEngine`的`execute`方法，传入流程ID和输入参数。
5.  **流程定义加载**：`RuleEngine`通过`FlowLoader`加载指定ID的`FlowDefinition`。
6.  **流程编排与执行**：`LiteFlowRuleEngine`将`FlowDefinition`转换为LiteFlow可识别的规则，并通过LiteFlow框架执行流程。
7.  **节点调度**：在流程执行过程中，`NodeExecutorRegistry`根据节点的`type`字段查找并调用对应的`FlowExecutor`（如`ServiceNodeExecutor`）。
8.  **上下文管理**：`FlowContext`贯穿整个执行过程，用于在节点间传递数据。
9.  **事件与拦截**：`ExecutionInterceptor`（如`LoggingInterceptor`）在节点执行前后及发生错误时被调用，`EventBus`发布流程开始、结束等事件。
10. **响应生成**：将`FlowExecutionResult`写入HTTP响应。

**本节概述了整体流程，未直接分析具体源文件，因此不提供章节来源。**

## 请求拦截与分发

`FlowDispatchInterceptor`是整个执行流程的起点，它是一个Spring MVC的`HandlerInterceptor`，负责拦截所有进入的请求。

```mermaid
sequenceDiagram

participant Interceptor as "FlowDispatchInterceptor"
participant Registry as "RestEntryPointRegistry"
participant Validator as "RequestSchemaValidator"
participant RuleEngine as "RuleEngine"
participant Response as "HTTP响应"
Client->>Interceptor : 发送REST请求
Interceptor->>Interceptor : preHandle()
Interceptor->>Registry : findMatch(method, uri)
alt 找到匹配的入口点
Registry-->>Interceptor : 返回RestEntryPoint
Interceptor->>Validator : validate(entryPoint, request, payload)
alt 校验失败
Validator-->>Interceptor : 返回错误
Interceptor->>Response : writeValidationError()
Interceptor-->>Client : 400 Bad Request
else 校验成功
Validator-->>Interceptor : 返回标准化参数
Interceptor->>RuleEngine : execute(ruleId, flowInput)
RuleEngine-->>Interceptor : 返回FlowExecutionResult
Interceptor->>Response : writeResponse(result)
Interceptor-->>Client : 200 OK + 结果
end
else 未找到匹配
Registry-->>Interceptor : 返回null
Interceptor-->>Client : 继续处理(可能由其他控制器处理)
end
```

## 流程定义加载与执行

`RuleEngine`是流程执行的核心协调者，它负责加载流程定义并委托给`LiteFlowRuleEngine`进行实际的流程编排。

```mermaid
sequenceDiagram
participant External as "外部调用者"
participant RuleEngine as "RuleEngine"
participant Loader as "FlowLoader"
participant LiteFlow as "LiteFlowRuleEngine"
participant Converter as "FlowDefinitionToLiteFlowConverter"
External->>RuleEngine : execute(ruleId, input)
RuleEngine->>RuleEngine : loadDefinition(ruleId)
alt reloadOnExecution为true
RuleEngine->>Loader : load(ruleId)
Loader-->>RuleEngine : FlowDefinition
else reloadOnExecution为false
RuleEngine->>RuleEngine : 从definitionCache获取
alt 缓存中存在
RuleEngine-->>RuleEngine : 返回缓存的FlowDefinition
else 缓存中不存在
RuleEngine->>Loader : load(ruleId)
Loader-->>RuleEngine : FlowDefinition
RuleEngine->>RuleEngine : 存入definitionCache
end
end
RuleEngine->>LiteFlow : execute(ruleId, input)
LiteFlow->>LiteFlow : registerRuleFromXml(ruleId)
LiteFlow->>Converter : generateXmlRule(definition)
Converter-->>LiteFlow : XML规则字符串
LiteFlow->>Converter : convertAndRegister(definition)
LiteFlow->>LiteFlow : liteFlowExecutor.execute2Resp(chainName, input)
LiteFlow-->>RuleEngine : FlowExecutionResult
RuleEngine-->>External : FlowExecutionResult
```

## 执行拦截与事件处理

`ExecutionInterceptor`和`EventBus`提供了在流程执行过程中插入自定义逻辑的机制，用于日志记录、监控或错误处理。

```mermaid
sequenceDiagram
participant Node as "节点执行"
participant Interceptor as "ExecutionInterceptor"
participant EventBus as "EventBus"
Node->>Interceptor : beforeNode(context)
Interceptor->>Interceptor : 记录日志 (e.g., LoggingInterceptor)
Interceptor-->>Node : 继续
Node->>Node : 执行节点逻辑
alt 执行成功
Node->>Interceptor : afterNode(context, result)
Interceptor->>Interceptor : 记录完成日志
Interceptor-->>Node : 继续
Node->>EventBus : publish(NodeFinishedEvent)
else 执行失败
Node->>Interceptor : onError(context, ex)
Interceptor->>Interceptor : 记录错误日志
Interceptor-->>Node : 继续
Node->>EventBus : publish(NodeErrorEvent)
end
Node->>EventBus : publish(FlowStartedEvent)
Node->>EventBus : publish(FlowCompletedEvent)
```

## 详细执行流程图解

以下流程图综合了上述所有阶段，展示了从接收到请求到返回响应的完整生命周期。

```mermaid
flowchart TD
A[客户端发起REST请求] --> B{FlowDispatchInterceptor}
B --> C{请求是否匹配<br/>HandlerMethod?}
C --> |是| D[不处理，交由AOP切面]
C --> |否| E{在RestEntryPointRegistry中<br/>查找匹配的入口点}
E --> |未找到| F[继续处理，可能由其他控制器处理]
E --> |找到| G[使用RequestSchemaValidator<br/>校验请求参数]
G --> |校验失败| H[返回400错误]
G --> |校验成功| I[构建FlowContext<br/>包含请求数据]
I --> J[调用RuleEngine.execute()]
J --> K{reloadOnExecution?}
K --> |是| L[FlowLoader.load()<br/>重新加载流程定义]
K --> |否| M[从definitionCache获取<br/>或加载并缓存]
L --> N[LiteFlowRuleEngine执行]
M --> N
N --> O{节点类型}
O --> |service| P[NodeExecutorRegistry.get('service')<br/>-> ServiceNodeExecutor]
O --> |rest| Q[NodeExecutorRegistry.get('rest')<br/>-> RestNodeExecutor]
O --> |其他| R[NodeExecutorRegistry.get(type)<br/>-> 对应的Executor]
P --> S[通过Groovy脚本解析输入参数<br/>调用Spring Bean方法<br/>将结果存入FlowContext]
Q --> T[从FlowContext获取参数<br/>调用外部REST服务<br/>将结果存入FlowContext]
R --> U[执行节点逻辑<br/>更新FlowContext]
S --> V{所有节点执行完毕?}
T --> V
U --> V
V --> |否| O
V --> |是| W[生成FlowExecutionResult]
W --> X[通过ExecutionInterceptor<br/>记录日志]
X --> Y[通过EventBus<br/>发布事件]
Y --> Z[将结果写入HTTP响应]
Z --> A
```
